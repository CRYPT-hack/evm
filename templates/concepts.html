📐 Discrete Mathematics Concepts

How discrete mathematics underpins every layer of this Electronic Voting System.

Project Context Each concept below is directly implemented in the codebase. Python (Flask) applies Set Theory and Functions in data management. C++ (verifier.cpp) implements all six verification checks using these mathematical principles.
🔷 Set Theory Checks 1 & 4

Where used: Storing unique voter IDs and transaction IDs to prevent duplicate voting.

V = {V001, V002, V003, ..., V010}
|V| = 10 (10 unique registered voters)

Rule: Each voter ID must appear exactly once in the vote records set. If a voter tries to vote again, their ID is already in set V — duplicate detected and rejected.

Duplicate check: |votes_set| = |votes_list|
If not equal → duplicate voter exists

C++ Implementation: std::set<string> seen_voters; — inserting into a set automatically enforces uniqueness.

📎 Functions Check 2

Where used: Mapping each Voter ID to exactly one Candidate ID (injective function).

f : VoterID → CandidateID
f(V001) = C1 (Aman Sharma)
f(V002) = C3 (Kabir Verma)

Injective property: Each voter maps to one candidate. The codomain must be ⊆ valid_candidates. Any vote outside this codomain is an invalid function mapping.

Valid: f(voter_id) ∈ {C1, C2, C3, C4}
Invalid: f(voter_id) = C9 → rejected

Python: validates candidate_id in valid_ids before recording. C++: checks each vote's candidate is in valid_candidates set.

🔢 Counting Principle Check 5

Where used: Counting total votes and verifying consistency of the count.

Total Votes = votes(C1) + votes(C2) + votes(C3) + votes(C4)
Total = Σᵢ votes(cᵢ)

Addition Principle: The number of elements in a disjoint union equals the sum of sizes. Each vote belongs to exactly one candidate, so summing per-candidate counts equals total votes.

Turnout = (Total Cast / Registered) × 100
Margin = Winner Votes − 2nd Highest Votes

C++ adds up vote_counts map values and compares to votes.size(). A mismatch means an invalid vote was included in a candidate total.

🧠 Propositional Logic All Checks

Where used: Encoding vote validation rules as logical propositions.

P: voter has already voted
Q: vote is accepted
Rule: P → ¬Q (if voted, then reject)

Compound conditions: All six verification checks are expressed as logical AND of propositions. The election result is valid only if all propositions evaluate to True.

Valid Election ⟺
¬Duplicate ∧ ValidCands ∧ ¬Negative
∧ UniqueTransactions ∧ Consistent ∧ ¬PHP_violated

C++: bool all_pass = !has_duplicates && !has_invalid_candidates && ...

🔗 Relations Data Model

Where used: Representing the voting relation between voters and candidates.

R ⊆ VoterID × CandidateID
R = {(V001, C1), (V002, C3), (V003, C2), ...}

Properties: The relation R is a function (not just a relation) because each voter ID maps to at most one candidate ID — the vote is unique per voter.

∀ (v, c₁), (v, c₂) ∈ R → c₁ = c₂
(Each voter relates to at most one candidate)

votes.json stores the relation as an array of (voter_id, candidate_id) pairs. C++ reads these pairs as VoteRecord structs.

🕊 Pigeonhole Principle Check 6

Principle: If n+1 items are placed into n containers, at least one container has more than one item.

n = registered voters (pigeonholes)
k = votes cast (pigeons)
If k > n → at least one voter voted twice

In this system: If total_votes > registered_voters, there are more votes than voters. By the Pigeonhole Principle, at least one voter must have voted more than once. This is a mathematical guarantee of fraud detection.

votes.size() > registered_voters
→ PHP violated → ERROR DETECTED

C++: bool pigeonhole_violated = ((int)votes.size() > registered_voters);
